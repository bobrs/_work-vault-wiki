# Operator Transfer, Model Succession, Retirement, and Residual State Matrix

Status: candidate pre-production  
Content canon status: unset

| Change | What may transfer | What requires renewed review |
|---|---|---|
| Operator transfer | Assets, records, bounded mandate | Nontransferable consent, open incidents, jurisdiction |
| Provider change | Service configuration, approved schemas | Provider constitution, memory, training reuse, refusal policy |
| Infrastructure migration | Encrypted records and tools | Custody, location, deletion, access controls |
| Model patch | Limited defect correction | Material behavior or policy change |
| Model replacement | Reviewed records and constraints | Runtime grant, capability, failure modes, notice |
| Fine-tune change | Declared specialized behavior | Source lineage, role, protected conditions |
| Provider model swap | Interface and workflow | Constitution, provenance, tool behavior, version identity |
| Rollback | Prior reviewed model and grants | Current corrections and incidents must still apply |
| Suspension | Witness and open claims | Conditions for restart |
| Retirement | Archival witness and named custody | Residual memory, credentials, appeals, compensation |
| Shutdown | Nothing active by default | Every surviving obligation and record class |

## Governing principles

> Operational continuity is not permission continuity. Model succession is a new constitutional event.

> The authority to stop acting is not the authority to abandon what remains owed.
