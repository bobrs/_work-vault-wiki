# HI-S — H/I Cross-Branch Synthesis, Conformance Freeze, and J Transition

## Purpose

Close the candidate H/I sequence before implementation.

The bridge should determine whether the public reader path and technical specification describe one coherent architecture rather than two parallel vocabularies.

## Required outputs

1. H.0–H.10 public-path synthesis;
2. I.0–I.10 technical-specification synthesis;
3. public-to-technical concept map;
4. cross-branch terminology freeze;
5. contradiction and omission audit;
6. schema-overlap and consolidation report;
7. canonical lifecycle and event vocabulary;
8. conformance-level definition;
9. minimum viable implementation profile;
10. privacy, security, misuse, and threat-model bridge;
11. reference-scenario selection;
12. Stage J opening recommendation.

## Required synthesis questions

- Does every public claim have a technical home?
- Does every required technical object have a public explanation?
- Are standing, authority, consent, permission, legitimacy, and witness used consistently?
- Are correction, release, withdrawal, dissolution, retirement, and deletion distinguishable?
- Do training, deployment, transfer, succession, and shutdown share one lifecycle grammar?
- Can conformance be tested without implementing the entire architecture?
- Which schemas are true common types?
- Which are domain profiles?
- Which remain research hypotheses rather than specification requirements?
- What minimum system could demonstrate the governing invariant end to end?

## Candidate conformance levels

```text
L0 — Witnessable Record
L1 — Source and Standing
L2 — Authority and Consent
L3 — Correction and Exit
L4 — Model and Tool Boundaries
L5 — Lifecycle and Successor Obligations
```

These levels are candidates only and must be audited in the bridge.

## Candidate Stage J opening

### J.0 — Reference Implementation and Pilot Harness

A small, inspectable implementation should demonstrate:

```text
source
→ projection
→ standing
→ authority
→ context
→ model role
→ route
→ tool gate
→ action
→ consequence
→ correction
→ release or retirement
```

Recommended reference scenario:

> A model-assisted community or institutional scheduling decision with participant correction, bounded tool use, witnessed consequence, and clean retirement.

## Shared gate

HI-S passes only if:

- H and I describe the same constitutional grammar;
- duplicated terms are consolidated;
- unresolved contradictions are named rather than hidden;
- the minimum conformance profile remains implementable;
- Stage J can begin without silently promoting research claims into production guarantees;
- repository D and E status remains explicitly unresolved until verified.
