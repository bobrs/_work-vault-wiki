# Canon of Persistence

## Purpose of this Document
This document states the **canon**: a minimal, physics‑respecting description of how any system persists over time, and shows how current projects map onto it. It also explicitly calls out gaps where the canon is not yet fully instantiated.

The canon is not a belief system, worldview, or metaphysical claim. It is a **constraint description**: if something persists, it must satisfy these conditions.

---

## The Canon (Minimal Form)

### Core Claim
> **Anything that persists does so by controlling the flow of energy, information, or resources across a boundary over time.**

No new physical laws are introduced. Only constraints, feedback, and time.

### Canonical Process (Irreducible)

1. **Energy / input arrives**
2. **Intake is gated** (a boundary exists)
3. **Storage buffers time** (state persists)
4. **Routing allocates flow** (direction, priority, intensity)
5. **Feedback loops update rules** (correction and learning)
6. **Failure is loss of correction** (boundary collapse or saturation)

If any step is missing or degraded, persistence fails.

---

## Canonical Operators (Derived, Not Independent)

These are not separate primitives; they are **functional requirements** of the process above.

### Boundary
- The distinction between inside and outside
- Required for identity and persistence

### Consent (Boundary Flow Control)
- The rule‑set governing when, how, and how much flow crosses the boundary
- Time‑bound, revocable, scope‑limited

### Witness (State Continuity)
- Memory sufficient to detect change, decay, violation, and replay
- Enables accountability and correction

### Refusal (Boundary Preservation)
- Negative feedback that prevents overload, coercion, or dissolution
- Thermodynamic necessity, not a moral claim

---

## Loop‑0 (Canonical Interpretation)

**Loop‑0** is the smallest stable instance of the above process:
- A boundary forms
- Intake is selectively gated
- Minimal storage enables delayed response
- Feedback preserves the boundary

Loop‑0 is not mystical. It is the **first non‑trivial control loop**.

## Global Gaps (Canon‑Level)

1. **Formal Spec Gap**
   - Canon exists conceptually but not yet as a strict type system or math‑like spec

2. **Refusal Semantics Gap**
   - Refusal is acknowledged but not always first‑class in implementations

3. **Time & Decay Modeling Gap**
   - Consent, identity, and trust decay curves are under‑specified

4. **Failure Taxonomy Gap**
   - Known failure modes exist but lack a unified canonical list

5. **Minimal Flagship Instantiation Gap**
   - No single end‑to‑end system demonstrates the canon with minimal surface area

---

## Canon Constraints (Non‑Negotiables)

Any compliant system must:
- Support refusal without penalty
- Detect and respond to overload
- Maintain sufficient witness for correction
- Allow renegotiation over time
- Fail safely when correction is lost

---

## Closing Statement

This canon does not explain meaning, morality, or purpose.

It explains **what must be true** if something is going to keep going.

Everything else — identity, dialogue, trust, culture — is layered routing built on top of this constraint.
