# Attractor System Roadmap — Lego Build Order 🧱

This roadmap defines the correct modular build sequence.

These are not one idea.

They are **three Lego bricks** that snap together:

1. Checkpointing (capture)
2. Compression-Witness (minting)
3. Attractors (living canon)

Ship in this order.

---

# Brick 1 — Checkpointing a Moment (Week 1)

## Goal
Save a living coherent moment as a **return path**, not a file.

## Feature
✅ “Checkpoint this moment” button in chat UI

## Output
Checkpoint Card:
- Label (tight compression with peer resistance)
- Reason (why this was worth saving)
- Compression ladder
- Residual seed
- Re-entry instructions

## Backend
One endpoint:
- POST /checkpoint

## Payoff
Immediate user value.
Foundation for everything else.

---

# Brick 2 — Dissent Shelf + Promotion (Week 2)

## Goal
Preserve runner-up variants as evolutionary siblings.

## Feature
Each checkpoint or attractor can hold:
- Canon
- Dissent bullets

Actions:
- Keep as dissent
- Merge into canon
- Promote dissent → new attractor

## Payoff
Meaning evolves without deletion.
History unfolds naturally.

---

# Brick 3 — Attractor Pages (Week 2–3)

## Goal
Make attractors the primary interface object.

## Feature
Attractor UI:
- Canon box
- Dissent shelf
- Parents (collapsed)
- Propose update input

Sidebar becomes attractor-first.
Search returns attractors, not files.

## Payoff
The app becomes a living knowledge basin system.

---

# Brick 4 — Compression-Witness Unification (Week 3)

## Goal
Mint new attractors only when economically inevitable.

## Feature
“Attempt Unify…” between attractors A and B

Law:
- Create unified U only if net compression gain
- Else preserve primes + mutual dissent

## Output
Unified attractor:
- Parents [A,B]
- Residual dissents preserved

## Payoff
Prevents attractor explosion.
Creates reverse-git lineage.

---

# Brick 5 — Reverse Git Lineage Navigation (Week 4)

## Goal
Excavate ancestry only when useful.

## Feature
Parents tab:
- show lineage graph backward
- selective depth dial

Payoff:
History without clutter.

---

# Brick 6 — Client Lens Rendering (Week 4+)

## Goal
Personal reinterpretation without rewriting canon.

## Feature
Local sliders:
- Spicy/Mild
- Fast/Deep
- Terse/Detailed

Lens changes rendering only.

Payoff:
No ontology wars.
Infinite personal bending.

---

# Brick 7 — Optional Bloom Features (Later)

- Meta-attractors
- Triangulated unification (3-way)
- Attention-credit scheduling
- Background reprocessing

Only after you have real usage.

---

1. Checkpoint button
2. Checkpoint Cards stored
3. Dissent + promotion
4. Attractor Pages
5. Compression-Witness unify
6. Reverse Git navigation
7. Lens personalization

Ship v0 fast.
Let meaning evolve.
