# Glyph Invocation and Reference

Working definition: in this vault, glyph communication has two modes. Invocation means the glyph is being used live as an act; reference means the glyph is being discussed as an object. The distinction keeps symbolic communication from collapsing action into description.

This page is an operational concept page, not a canon declaration. It compresses the usage rule that shows up across glyph, protocol, and communication branches.

## Core Motifs

- invocation as act
- reference as mention
- default to reference when uncertain
- live signal versus discussed symbol
- glyph syntax as communication control
- machine consistency in mixed human/AI use

## Why It Matters

The same symbol can either change the local state of a conversation or remain part of the sentence about that state. If the system does not mark that difference, a glyph can be misread as command, endorsement, or event when it was only being named.

That is why this is useful across protocol design, communication substrates, and glyph-heavy narrative systems: it preserves a clean line between doing and saying.

## Notes

- Invocation uses `;word glyph`.
- Reference uses `word [glyph]`.
- If uncertain, default to reference.
- AI should keep both the word and the glyph when it needs to invoke or reference a symbol.
